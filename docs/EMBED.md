# 温室与自己的网站

温室是独立的静态应用，不读取 GitHub 活动、实例配置或 review token；不启用自动化也能完整游玩。

## 离线打开

下载 `garden/index.html`，用浏览器直接打开。脚本、样式和 SVG 插画已内联，不需要 npm、后端、服务器或账号。

## 放到现有网站

把单个 `garden/index.html` 复制到自己网站的静态目录。例如 Astro、Next.js 等项目可以使用：

```text
public/
└── garden/
    └── index.html
```

沿用网站原来的正常发布流程，上线后访问 `/garden/`。不需要新建服务或每日重新发布：日期、天气和访客都由浏览器计算。如果网站已有同名路径，请选择其他空闲路径，不覆盖原页面。

温室自身不含个人域名或仓库链接。可以按自己网站的设计添加导航；这属于网站自定义，不应把个人配置再提交到通用模板。

## 作为 iframe 嵌入

页面已放在同源 `/garden/` 时，可在自己网站的合适位置添加：

```html
<iframe
  src="/garden/"
  title="每日一盆小温室"
  loading="lazy"
  style="display:block;width:100%;height:960px;border:0;border-radius:20px"
></iframe>
```

高度可按页面布局调整；较窄屏幕下内容更长，应给足滚动空间，也可以直接提供“进入温室”的链接。无需授予摄像头、定位或麦克风权限，不要为嵌入而放宽整个网站的安全策略。

若改用其他域名，浏览器或网站的 iframe/CSP 策略可能限制嵌入；优先使用自己站点的静态路径，或直接链接到温室。不要自动修改用户的 DNS、认证或全站 CSP。

## 收藏会跟着走吗

收藏和访客印章使用浏览器 `localStorage`，同一来源的页面共享存储。换域名、浏览器或从本地文件改为网站后，收藏通常不会自动迁移。第三方 iframe 还可能受到浏览器存储限制。

同源的其他脚本可能访问这些普通存储；这不是敏感数据的保险箱。详见[隐私说明](../PRIVACY.md)。

## 修改后更新

编辑三个植物/访客源脚本后，在源码根目录运行：

```sh
python3 -B scripts/build_greenhouse.py
```

将新生成的 `garden/index.html` 重新复制到自己网站，再用原有发布流程发布一次即可。不要添加每日构建、API 拉取或 Actions 巡检。保留现有种子前缀与存储键，或编写迁移后再更改，以免原有植物与收藏失去兼容。
